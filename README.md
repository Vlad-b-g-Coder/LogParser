# Вариант 19. Парсер логов

Приложение на C# (.NET 8) собирает логи из разных источников (файлы, вставленный текст, stdin, сторонний сервис с нестандартным API, ответ pegast.ru) в разных форматах (JSON, key=value, CSV) и показывает их в одной таблице. Есть графический интерфейс (WPF) и консольное демо.

## Интерфейс

Для запуска нужны Windows и .NET 8 SDK.

```
dotnet run --project LogParser.Wpf
```

Что умеет окно:

- **Кружки проверки источников.** Каждый источник загружается сразу при добавлении, и рядом с ним появляется статус:
  - зелёная галочка: источник работает, все строки разобраны;
  - жёлтый «!»: загружено, но часть строк пропущена или записей нет;
  - красный крест: источник недоступен (например, файла нет), причина написана под названием;
  - серая точка: ещё не проверялся; синяя крутилка: идёт загрузка.
- **Общий «светофор»** в заголовке панели и в строке состояния: красный, если упал хоть один источник, жёлтый при замечаниях, зелёный, когда всё исправно.
- **Добавление источников:** кнопка «Файл…» (можно сразу несколько), перетаскивание файлов в окно, «Текст из буфера…», «Сервис мониторинга» (демо адаптера), «pegast.ru…», «Загрузить пример». Формат файла определяется автоматически или выбирается вручную.
- **Действия над источником:** галочка «учитывать в таблице», перечитать (⟳), убрать (✕). Кнопка «Обновить все» перепроверяет все источники.
- **Таблица записей** со сквозной сортировкой по времени, цветными кружками уровней и панелью подробностей с кнопкой «Копировать».
- **Фильтры:** минимальный уровень, поиск по тексту и источнику, интервал дат. Счётчики уровней над таблицей кликабельны.
- **Экспорт** того, что сейчас видно в таблице, в TXT, CSV или JSON.

## Консольное демо

```
dotnet run --project LogParser.Cli
```

Показывает те же классы без интерфейса: загрузку из двух источников, фильтр по уровню, подключение остальных источников (включая несуществующий файл), поиск и сохранение отчёта в `reports/report.txt`.

## Использованные паттерны

### Adapter (адаптер) — `LogParser.Core/Sources/LogSources.cs`
**Проблема.** Сторонний сервис `VendorMonitoringService` имеет несовместимый API: постраничная выдача, время в Unix-секундах, уровень числом. Менять его нельзя, а остальной код ждёт единый `ILogSource`.
**Решение.** `VendorServiceAdapter` реализует `ILogSource`, внутри вызывает сервис, постранично забирает записи и переводит их в `LogEntry`. Второй адаптер, `PegastSearchAdapter`, подключает ответ поиска pegast.ru (JSON с `resultItems`, вложенные цены, дата вылета): каждый найденный тур становится записью лога, тур с ночами в пути получает уровень Warning (демо-правило). Файл, stdin и вставленный текст реализуют тот же интерфейс через общий `LineLogSource`. Новый источник = новый класс, существующие не меняются.

### Facade (фасад) — `LogParser.Core/Facade/LogParserFacade.cs`
**Проблема.** Интерфейсу (и консоли) не нужно знать, сколько источников и форматов внутри и как они читаются.
**Решение.** `LogParserFacade` прячет всё за небольшим набором методов: `Add()`, `Load()`/`Reload()`, `Query()`, `FilterByLevel()`, `SaveReport()`/`Export()`. Он хранит состояние каждого источника (`SourceStatus`: зелёный, жёлтый или красный кружок), собирает записи в единый список по времени, а сбой одного источника не роняет остальные.

Форматы (JSON, key=value, CSV) вынесены в `ILogLineParser`, поэтому формат и источник комбинируются независимо: например, CSV можно читать и из файла, и из вставленного текста.

## Структура

```
LogParser.sln
├── LogParser.Core/                  # вся логика, без привязки к интерфейсу
│   ├── Models/LogEntry.cs           # единая запись и уровни
│   ├── Parsers/LogFormatParsers.cs  # JSON, key=value, CSV, автоопределение формата
│   ├── Sources/LogSources.cs        # ILogSource, файл, stdin, текст, Adaptee + адаптеры
│   ├── Facade/LogParserFacade.cs    # Facade, статусы источников, фильтры, экспорт
│   └── Data/                        # примеры логов и ответ pegast.ru
├── LogParser.Wpf/                   # графический интерфейс (MVVM)
│   ├── Controls/StatusBadge.*       # кружок состояния
│   ├── ViewModels/                  # MainViewModel, SourceItemViewModel
│   ├── MainWindow.xaml(.cs)         # окно
│   └── PasteTextWindow.xaml(.cs)    # диалог «Текст из буфера»
├── LogParser.Cli/Program.cs         # консольное демо
└── docs/class-diagram.puml
```

## Что показывает консольное демо

1. Загрузка из двух разных источников (JSON-файл и сторонний сервис через адаптер).
2. Фильтрация по уровню (Error и выше).
3. Подключение ещё четырёх источников (CSV, key=value, stdin, pegast.ru) и одного несуществующего файла: ошибка не роняет остальные.
4. Поиск по тексту и сохранение отчёта (Warning и выше).
